SAMPLE PROJECT NOTES AND SVG MAP TUTORIAL
=========================================

NOTE: To run an introductory tutorial demonstrating basic operations
such as data entry, select File | Open and navigate to Tutorial.prj in
the \Walls\Projects\Tutorial Project folder. Then return to this sample!

This sample project was derived from the Jan 2003 data set for Actun
Kaua, a maze cave in Southern Mexico. Encompassing only one section, the
North Maze, its main purpose is to illustrate SVG import and export. The
attached SVG source file, KAUA-NM_w2d_mrg.svg, is incomplete. It
contains only passage outlines, a legend, some notes, and a few features
in the Detail layer. Instead of UTM coordinates (the usual choice), the
coordinates used here are NAD27 UTM grid- relative meters with respect
to the cave entrance.

Before reading the rest of these notes, perform the following steps
to see how an SVG map view will be generated most of the time:

1) Compile the root. The preview map should show the last saved
   view (not the default view) since the saved view was active when
   the Review dialog was last closed. If you check the Scale &
   Position dialog, you should see that the view frame's center is at
   (-10,150), the scale is 1:300, and the frame size is 50 x 38 in.

2) Open the SVG Export dialog by clicking the toolbar button labeled
   "SVG" (right-pointing arrow underneath).

3) If you're interested in knowing about the options at this stage,
   press F1; otherwise, accept the initial defaults and click "OK".

Step 3 should launch the SVG viewer, Walls2D, with the newly
generated SVG. If it doesn't, then the viewer will probably be
telling you that you need to install Adobe's free plug-in, ASV 3,
which it depends on. In that case, a link to the plug-in's download
page is displayed in the About box.

The operation you just performed, called a "merged export",
processed a "source SVG" named KAUA-NM_w2d_mrg.svg. Maps with
different frame sizes, scales, and views can be created using this
file. To see this, close Walls2D and zoom to an arbitrary portion
of the Kaua maze, possibly changing the view direction. Then do
another SVG export while using the same export options. Note that
for these exports, style and color attributes are inherited from
the source SVG and don't depend on settings on the Segments page
of the Walls Review dialog.

Making the source SVG file a tree item insures that it will be included
in any backup archive. If attached with a connecting line, it serves as
the default source for merged SVG exports when a higher-level book is
being reviewed. Also, when such a book is being compiled, the SVG is
(optionally) processed along with survey data files. The result is that
when maps are rendered by Walls itself (not Walls2D), filled SVG passage
outlines can be shown in place of representations based on LRUD
measurements.

To demonstrate this, without changing the view you just examined in
Walls2D, check the box adjacent to the "Passage" button on the Map
page's control panel, then click Display to generate a screen map. With
this map window active (not the preview map), change the view and
display options via the right-click context menu, or by zooming (mouse
scroll wheel or left-dragging) or panning (right-dragging) with the mouse.
Note that color and style attributes, in this case, were taken from
settings on the Segments page. They were not inherited from the
processed SVG.

When generating new SVGs from a source SVG, you can also choose NOT to
inherit styles and colors. For example, try this: On the Segments page,
change the Background color from black to light gray and the Passage
Floors color from dark gray to a dark red-brown. Next, open the SVG
export dialog and click the Walls check box in the Merged Layers section.
This will turn the bold checkmark to gray, which specifies that the Walls
layer will initially be turned off in Walls2D. Next, to make your color
settings override those of the merged source file, uncheck the "Preserve
styles and colors" box in this section. Now, when you select OK, Walls2D
will display a more dramatic representation of the maze.

This particular source, KAUA-NM_w2d_mrg.svg, happens to have been
generated by Walls in a previous export that merged (and morphed)
an Illustrator 10 SVG. Therefore, when you use it now to export a
new view, a feature adjustment is not required. The process is
relatively fast.

One way to see feature adjustment in action is to Attach the second
fixed point, the tree item named "2nd Fix that Moves W2 10m North".
(Read the comments in that file.) Then, after recompiling the project
root, do another merged SVG export. You'll see that stretching a
260-meter long section of maze by only 10 meters will not change the
map enough to be noticed, no matter where you look. You'll need to
change specific shots to see any local effects of morphing. The
feature adjustment, by the way, is more complex than a "rubber sheet"
style warp. Depending on the graphics layer, some features are only
scaled and translated. Also, nearby survey vectors, not a superimposed
mesh, control the adjustment. Features that require morphing include
passage outlines, floor details, and special effects like gradient
color fills.

Be sure to try a merged export both with and without the "Run
Walls2D" option enabled. When you don't run the viewer, some
interesting statistics are displayed instead. You can then launch
the viewer with a toolbar button labeled "2D".

To obtain an updated version of the source SVG -- that is, a new SVG
reflecting survey changes that in turn can be used as a source -- you
would likely want to use the same frame and view settings even though
it's not a requirement. The settings used by KAUA-NM_w2d_mrg.svg are
frame: 50"x38", scale: 1:300, center coordinates: (-10,150). The only
thing necessary for an exported SVG to qualify as a source is that
the "Adjustable" option be turned on in the export dialog. (It is off
initially.) This stores metadata in the file and makes adjustment
(and opening in Illustrator) possible.

Although an Illustrator SVG could just as easily have been used as
a source SVG in this example, the Walls version is typically smaller
and contains comments to assist anyone who might want to edit the SVG
text directly. Inspect it by double-clicking the "KAUA-NM_w2d_mrg.svg"
icon. The "w2d_mrg" component of the file name is not a requirement
but a naming convention that helps us (not Walls) recognize the
type of SVG it is. "wd2" means that it was written by Walls, not
Illustrator. "mrg" means it can be used as a source file for merged
exports.

Finally, note that the attached source SVG has extension ".svg", not
".svgz". The latter extension would have indicated we were using a
"gzip-compressed" SVG, a type of file that most SVG-capable programs,
including Walls, can read and write. The only reason we're using an
uncompressed source SVG is so that it can be opened with the Walls text
editor as suggested above. Switching to a compressed version,
KAUA-NM_w2d_mrg.svgz, would reduce file size from 1.1 MB to 341 KB.

For a more complete coverage of SVG operations in Walls, see the
help file section "Roundtripping SVG Maps". Also, be sure to check
out the sample project in Walls\Projects\Tutorial. It has
another SVG source file you can experiment with.
